# Design: P2 工作接续

## Context

动机见 `proposal.md`；P0 提供租约与 Effect Gate，P1 提供隔离工作区与确定 ContextBundle。P2 只解决「执行者或负责人变化后如何继续」，不增加协作图或发布链（§40.1 P2）。

## Goals / Non-Goals

- 目标：在真实两个运行配置上完成执行接续与负责人切换；旧写入未停、脏文件、丢回包、旧命令重放均有可判定出口。
- 目标：接续等级与证据分项可查，不能把候选说明当权威事实。
- 非目标：任意厂商无损切换、导出内部思维链、自动迁移全部工具状态、多 Agent 合并队列、远程节点与移动审批。
- 非目标：把 `reportsTo`/组织图元数据变化当作管理权迁移。

## Decisions

1. **等级显式化。** L1 只交接资料，L2 重建现场，L3 需已测运行时/工具/任务组合并先验证再继续；未满足条件的自动接续被拒绝但部分包仍可登记（§18.9）。
2. **规范编码 + 内容摘要分离。** payload 采用固定 UTF-8、键顺序、时间/数字编码与数组顺序；payload_digest 不计入自身递归计算，原始文件另按字节摘要（§18.10）。替代方案是自由文本摘要，无法跨语言校验。
3. **事实与叙述分栏。** 宿主从版本化工作区、成果、Effect 与预算快照生成骨架；Agent 只补充叙述，done 自述无证据保持 unverified（§18.11）。
4. **切换意图持久化。** 不在数据库事务内等待总结或传大文件；用持久意图与阶段状态协调，最终绑定以 expected_version 条件提交，重复 accept 幂等（§18.12）。
5. **先停旧再写新。** 旧执行停止未确认或无法隔离时，禁止新执行者写同一现场或重发相关外部动作；只允许已证实隔离且无相关副作用的独立工作（§18.12、§20.9）。
6. **对账 hint 不可信。** Agent 自述的 URL、脚本或命令不执行；实际查询只走注册连接器、授权目标与受限参数，不明只阻塞相关动作（§18.12）。
7. **管理权与执行权分离。** 管理凭据绑定 Appointment、epoch、scope、命令集与 audience；旧 epoch 命令被拒，员工独立执行身份继续；交接包不授予管理权（§31.10、§19.14）。
8. **符合性先于支持声明。** `bod conformance` 复用 schema/fixture/状态映射；基础身份、授权、消息完整性失败禁用派发，可选能力只在声明支持时验证（§15.10）。

## Risks / Trade-offs

- [旧进程持有长期凭据] → 停止确认/隔离失败即阻塞新执行；披露为已知覆盖缺口，不承诺 token 自动阻止第三方写入（§10.6）。
- [部分交接不可用] → 保留 missing 与完整性状态供人工恢复，自动接续按等级拒绝；不因字段缺失丢弃唯一现场。
- [换人篡改历史] → Artifact/Revision/费用主体与旧决定不可变；争议记录标待核查（§21.15）。
- [双运行时样本不足] → conformance 报告列样本数与未覆盖项，不宣称任意厂商无损切换。

## Migration Plan

在 P0/P1 数据库上追加 handoff_packages、takeover_transactions、checkpoints、manager_transfers、conformance_reports 与事件类型。历史 Attempt 无 checkpoint 时只能提供 L1 资料交接或标 unknown；不补造现场。回滚保留旧委任与执行记录，恢复后按当前 epoch 重新校验。

## Open Questions

- 第二个真实运行时的具体版本由 conformance 实测选定；不改变接续等级、事务步骤或 epoch 语义。
- 管理负责人切换的 UI 呈现可在试点调整，但旧命令拒绝、员工继续与增量读取属于规格，不在本层变动。

# Design: P5 复用与团队

## Context

动机见 `proposal.md`；P0—P4 已提供可信核心、真实交付、接续、协作与运行证据。P5 加入多人复用与一个通道，但不默认开放公网入口或多租户（§31.2、§40.1 P5）。

## Goals / Non-Goals

- 目标：团队可安装/升级/卸载一套协作配置且不覆盖本地修改；六阶段权限有可复现拒绝样本；反馈可沉淀为可撤销约定；一个通道能处理待决定与回执。
- 非目标：SDK、第三方适配市场、远程节点、移动原生/H5 全链路、容量引擎迁移、在线市场。
- 非目标：把外部材料或角色称号当权限凭证；把客户反馈自动升级为组织规则。

## Decisions

1. **Catalog 是配置包，不是授权。** 安装选择确定版本、校验来源/完整性/许可证、预览对象与冲突、明确授权后事务记录；包名和目录推荐不授予管理员权（§6.4—6.5）。
2. **三方升级保留本地修改。** 比较原包基线、当前本地修订与新包版本；冲突时保留本地并生成提案，新增权限/外部程序/付费连接必须重新准入（§6.5）。
3. **权限矩阵服务端判定。** 六阶段动作统一由宿主按成员身份、ProjectAccessGrant、目标归属和当前状态解析；列表/搜索/导出/订阅在返回前过滤，拒绝不生成派发或通知（§31.15、§34.12）。
4. **反馈走最窄作用域。** 默认当前工作包 → 项目 → 指定客户/角色；扩大到组织需独立授权。权限、密钥、预算与生产发布转治理流程，不由学习服务执行（§23.2—23.4）。
5. **知识修订不可变。** FeedbackProposal 与 Profile/Skill 修订走 ArtifactRevision 与 expected_base_revision；并发冲突保留提案，下一次 Attempt 固定新修订，旧 Attempt 不切换（§22.1、§23.3、§23.6）。
6. **缓存先授权后返回。** Profile/Skill/规格缓存按 revision/digest 复用并复核当前权限；敏感删除和撤权优先失效，正式 Manifest/CAS/账本不是可淘汰缓存（§22.4）。
7. **通道只投影宿主事实。** 卡片包含待决定、待验收、待回访；动作绑定成员、项目、目标、修订和命令键，宿主在线时重验权限与版本，离线显示最后更新或待同步（§30.9）。
8. **接收与投递分开。** 渠道接受消息只证明接收请求；仅在渠道提供观察时记录投递/已读。回滚或修订变化后按投递键发送更正，旧回调只补历史（§30.10）。

## Risks / Trade-offs

- [团队配置漂移] → 三方升级与冲突提案保留本地差异，安装记录带 digest；不按名称覆盖对象。
- [跨客户泄露] → 权限过滤在服务端返回前执行，六个 AZ 用例覆盖回执、凭据、分派、验收、发布与订阅。
- [学习管道被注入] → 外部 PR 评论/网页/工具输出不可信；自动接受规则限定 actor、目标、字段、范围与有效期。
- [通道回包丢失] → 按投递键或外部引用查证，无幂等能力标待核实并人工处理，不把消息已发当业务成功。

## Migration Plan

追加 catalog_install_records、project_access_grants、feedback_proposals、knowledge/preference_revisions、channel_bindings、delivery_receipts 与事件。历史成员与 Issue 缺显式 Grant 时按现有默认行为运行但不标团队已验收；跨客户回执缺外部标识时标待核实。回滚保留 P0—P4 数据与交付证据，卸载配置包不删除项目资产。

## Open Questions

- 首个团队通道由试点现有 IM 决定；不改变卡片投影、命令绑定与投递回执规则。
- Catalog 包的具体格式版本由 conformance 样本固定，不因 UI 目录调整改变安装与升级语义。

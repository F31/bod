# Spec Delta: remote-execution

## Purpose

定义远程节点与 webhook 的委派、签名、游标、分区与恢复边界，使外部执行不破坏宿主的唯一写权和 Unknown 对账纪律。

## ADDED Requirements

### Requirement: 委派契约

节点与 webhook SHALL 共用启动请求结构，并携带项目、目标设备、交接包版本与摘要、执行级 grant、预算预留、策略版本；管理动作另附 Appointment 与 authority_epoch。参数摘要 SHALL 随 invocation 持久化，同 ID 异参拒绝。

#### Scenario: 篡改委派参数
- **WHEN** 节点用同一 invocation 但改动工作区或预算参数重送委派
- **THEN** 宿主拒绝并保留原记录，不创建新执行

### Requirement: 签名事件批次与游标

事件批次 SHALL 包含节点标识、密钥版本、执行实例、起止 source_sequence、事件摘要与签名；宿主 MUST 验签并按来源去重，缺序请求补传，持久化后确认连续游标。重送合法批次 MUST 只入账一次。

#### Scenario: 篡改批次后重送
- **WHEN** 一个被篡改的批次被拒绝后重送原合法批次
- **THEN** 宿主拒绝篡改内容，合法批次只入账一次，验收仍需独立证据（RM07）

### Requirement: 失联与旧节点恢复

失联时 SHALL 暂停新的受管外部动作并持久化未上传事件，显示连接未知；恢复时 MUST 先核对授权 epoch、租约、尝试、游标与外部动作记录。旧节点迟到完成保留签名证据，过期 token MUST NOT 修改宿主受管状态；最终项目只有一份被接受的交付。

#### Scenario: 租约过期后新尝试完成
- **WHEN** 租约过期后建立新 Attempt 并完成，旧节点随后提交完成
- **THEN** 旧报告保留在旧 Attempt 历史，权威结果与预算按实际用量对账，无重复验收（RM03）

### Requirement: 外部动作对账

外部写入已发送但结果未知时 SHALL 按稳定业务动作 ID 查询目标；可查询目标只补记一次，不可查询目标显示待核实且无第二次盲写。目标不能查账或隔离旧写入时 MUST 阻塞冲突动作并列出核实责任人。

#### Scenario: 外部动作已生效但节点掉线
- **WHEN** 目标系统已生效而节点掉线、租约过期
- **THEN** 宿主按业务键补记一次或不显示待核实，不重复写（RM02）

### Requirement: 设备授权与撤权

配对与在线只说明设备可识别、链路可用；设备能力与用户项目权限 MUST 取交集。新增远程业务通道默认关闭，启用须声明命令与作用域；关闭后 MUST 终止控制会话并拒绝排队中未生效命令，已发外部操作按对账处理。

#### Scenario: 离线期间关闭交办权
- **WHEN** 设备具有交办权但离线期间该权被关闭
- **THEN** 重连后排队的交办命令不生效、停止命令被拒，获准查看继续（SB05）

### Requirement: 传输与信箱边界

HTTP/SSE SHALL 为基线，列表只收授权内摘要，详情按会话订阅；慢订阅者超限释放缓冲并按最后持久游标补拉，游标过期读带基准序列快照。中继只检验信箱投递授权，业务决定仍由宿主裁决；信箱满额或消息过期 MUST 明确反馈且至多一次有效业务决定。

#### Scenario: 切网与游标过期
- **WHEN** 慢订阅、切网与游标过期同时发生
- **THEN** 释放队列、从快照基准补齐，控制命令显示真实回执而非成功假象（RM06）

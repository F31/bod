# Design: P6 按需开放

## Context

动机见 `proposal.md`；P0—P5 已建立本地可信核心、交付证据、团队权限与一个通道。P6 只开放经验证的外部边界，不把远程或移动作为本地首发前提（§40.12—40.13、§41.10）。

## Goals / Non-Goals

- 目标：第三方不改宿主即可安装适配；远程节点按能力委派并可对账；只读查询无业务副作用；移动审批与 H5 回执按分期有真机证据。
- 非目标：在线市场、原生 ICE、多宿主 MQ、受监管行业定制、按 Agent 数量计价、把 QUIC 默认化。
- 非目标：把 HTTP 拒绝当运行环境隔离，把协议定义当实现支持，把渠道接收当客户确认。

## Decisions

1. **能力协商先于派发。** 节点与 webhook 共用启动结构，启动前按版本与必需能力握手；缺结果查询/持久去重/签名的端点只能承接其声明能力范围内的工作（§15.11）。
2. **签名批次与持久游标。** 事件批次含节点标识、密钥版本、起止 sequence、摘要与签名；验签后按来源去重，缺口请求补传，持久化后确认连续游标（§15.11、§34.11）。
3. **单一宿主裁决。** 节点只按任务获得工作区与凭据；失联时暂停新外部动作，恢复先核对 epoch/租约/尝试/游标/effect 再决定。旧节点迟到结果保留证据但拒绝过期 token 更新宿主状态（§20.9）。
4. **设备权限与业务权限取交集。** 配对/在线只说明设备可识别、链路可用；新增远程业务通道默认关闭，启用须声明命令与作用域并测试；关闭后拒绝排队中未生效命令（§31.16）。
5. **HTTP/SSE 基线。** 列表只收授权内摘要，详情按会话订阅；慢订阅者释放缓冲后按最后持久游标补拉，游标过期读带基准序列的快照。QUIC 单独对照，只有预登记指标有可重复收益才发布（§34.11、§40.12）。
6. **只读先授权后返回。** 列表/搜索/计数/导出/订阅/附件下载在返回前过滤；只读命令不启动 Agent、不改控制状态，审计与有界计算允许（§34.12、I-55）。
7. **移动分期与真机证据。** P2 阶段做管理端伴随与 H5 提交/回执，P3 再补 diff/批注、发布、覆盖视图等；宣称全流程须有 MD01—MD04 与目标平台证据（§40.13）。
8. **出站数据范围可解释。** 首次向外部模型/插件/连接器发送材料时展示项目、资料范围、接收服务与账号；范围或账号变化重新判断，日志只留引用与摘要（§31.16）。

## Risks / Trade-offs

- [远程写冲突] → 旧写入未隔离时阻塞冲突目标，只允许隔离的独立工作；Unknown 先对账不盲重发（§20.9）。
- [信箱/游标不一致] → 容量与过期有边界，冲突决定至多一次生效；游标缺口触发补传，不以无告警为健康。
- [切网误判] → 按最后确认事件与待确认命令对照，分别记录传输连接与业务会话恢复；样本不足保留 HTTP/SSE 基线。
- [移动端签名与修订竞争] → 旧签名不能接受新成果，撤销阻断生效，重新核对并签署新修订才生成回执（MD02）。

## Migration Plan

追加 adapter_descriptors、node_registrations、device_grants、event_batches、cursors、mailbox_messages、readonly_bindings、mobile_signatures 与相应事件；本地无远程配置时所有远程端点默认关闭。历史执行无签名标「无节点签名」，不补造证据。回滚保留 P0—P5 数据与本地执行能力，先验证远程关闭时本地单机安装、首项目与升级流程。

## Open Questions

- QUIC/隧道/中继与自托管信箱的具体产品选型由真实网络对照决定；不改变能力协商、分区与对账语义。
- 移动端首批平台与分发地区由试点设备与通知服务决定；不改变六段流程分期与签名/撤销规则。

# 架构决策记录（ADR）

本目录记录**与 V2.9.6 技术架构规格不一致、或规格未覆盖**的技术选择。

## 为什么需要这个目录

规格第 5 行自己写明：「文中模块、接口与性能数值分别表示**拟议**边界、契约和测量目标，
实现及验证状态由支持矩阵记录」。所以偏离本身不违规——但**沉默的偏离**违规。

参考库的纪律是：实现与规格冲突时，「要么改代码，要么新增 ADR 说明为什么推翻原决策，
两者必有其一，不允许悄悄漂移」。这个目录就是那条纪律的落地位置。

## 为什么不在 `docs/` 下

`.gitignore` 第 54 行把整个 `docs/` 排除在版本库外（文档与规格手册只留本机）。
决策记录必须随代码走，否则换机器、换协作方就丢了上下文，所以放在仓库根级的 `adr/`。

## 状态语义

| 状态 | 含义 |
|---|---|
| `proposed` | 已记录，尚未执行；代码可能仍是旧形态 |
| `accepted` | 已采纳，代码按此实现 |
| `superseded by NNNN` | 被后续 ADR 取代，保留原文不改写 |
| `rejected` | 讨论过但未采纳，保留理由避免重复讨论 |

**撤销条件必须写成可机械判断的形式**。写「复杂度上升时重评」等于没写——谁来判断上升？
写「单进程并发订阅 > 50」才有意义。

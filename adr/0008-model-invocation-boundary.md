# ADR-0008 模型调用：首版只用规则摘要，不接模型客户端

- 状态：`accepted`
- 日期：2026-11-22
- 决策者：项目负责人（2026-11-22 授权按评审推荐方案执行）
- 关联：V2.9.9 技术规格 §12；产品方案 §29.8 / §39.25；ADR-0004（契约单源）
- 取代：无

## 场景

产品方案 §29.8 写「AI 可提取候选关联、指出缺口、建议下一步、起草措辞」，§39.25 有一条验收
「不配置模型，且接入前已有旧版内部交付 → 可用规则摘要完成人工答复」。

仓库现状（2026-11-22 检索）：**没有任何模型客户端**——`openai` / `anthropic` / 模型路由
零命中，`reqwest` 未引入，唯一相关的是 `observation_redaction` 的脱敏辅助。也就是说，
「AI 起草」这句话目前**没有任何实现路径，也没有对应的信任边界决策**。

而这条能力要处理的内容恰恰最敏感：客户名、环境标识、缺陷描述、内部工作包标题。
它一旦出本机，牵动 §31 身份权限、§33 数据边界、§38 可观测性三处。

## 决策

**首版（P8 及 V2.9.9 周期内）不接任何模型客户端。** 草稿由「规则摘要 + 人工编辑」生成，
结论与将来的 AI 路径**必须一致**——因为结论本来就由 `coverage_receipt::judge_coverage` 判定，
模型只能改写措辞，不能改变判定。

「AI 起草」登记为 **Capability（未实现）**，不是 Milestone。引入它必须另开一份 ADR，
不得在实现草稿状态机时顺手接上。

## 三种模式的比较（供将来那份 ADR 直接引用）

| | ① 仅本地模型 | ② 外部 API + 字段投影 + 显式授权 | ③ 首版不做（本决策） |
|---|---|---|---|
| 数据出本机 | 否 | **是**（投影后仍含客户可见事实） | 否 |
| 部署成本 | 需随包分发权重或要求用户自备运行时 | 无 | 无 |
| 质量 | 受本地小模型能力限制 | 最好 | 取决于人工 |
| 合规/客户同意 | 无需额外告知 | 需逐客户同意与开关 | 无需 |
| 失败模式 | 模型不可用 → 回退规则摘要 | 网络/配额/供应商变更 → 回退规则摘要 | 无 |
| 结论 | 可作第二步 | 需客户书面同意后才可评估 | **本版采用** |

## 理由

1. **结论与措辞必须解耦，而现在只做到了结论。** `judge_coverage` 是纯函数、有命名用例；
   措辞是外部依赖。先交付「判定 + 人工措辞」，价值验证（§40.15 的净节省）就能成立，
   不必等模型。
2. **没有信任边界决策就接模型，等于把「数据会不会外发」交给实现者临场判断。** 这正是
   A9（安全忽略）的典型形态。
3. **回退路径已经被规格写死，不是权宜之计。** §39.25 明确要求「不配置模型也能完成答复」，
   所以规则摘要不是降级版，是**基线**。

## 代价

- 草稿初稿质量依赖人工，首次答复耗时高于「AI 一键起草」的竞品演示。
- 需要额外做「规则摘要」的文本模板与缺口清单措辞（约 1 个切片的量），不能省。
- 对外沟通时不能宣称具备 AI 起草能力——按仓库纪律，未实现的能力不得写进支持矩阵承诺。

## 撤销条件（可机械判断）

1. 出现 ≥1 个真实试点明确要求 AI 起草，且能提供**已脱敏**的样本集与客户书面同意；
2. 本地模型在目标机实测单次起草 p95 ≤ 500 ms 且常驻内存 ≤ 500 MiB（可随包分发）；
3. 供应商方案能提供「不保留请求内容」的合同条款与可审计的区域固定。

任一满足即另开 ADR 重评，且**不得**在本 ADR 上直接改状态为「已实现」。

## 落地要求（引入时）

- 字段投影白名单：只有标记为「对外可见」的字段可进入提示词，对内事实永不入模；
- 每次调用写 `audit_events`，带 `correlation_id`，保留模型标识与提示词摘要（**不留正文**）；
- 模型不可用、超时、拒答三类失败都必须回退到规则摘要，且结论不变；
- 同一组证据下「有模型/无模型」的 `CoverageVerdict` 必须相等——这条要成为回归用例，
  不是人工约定。
